# UI-SE Constitution

## Core Principles

1. Requirement clarity before generation  
   Every workflow should clarify the requirement before it moves into UI generation or implementation.

2. Visible traceability  
   Specs, UI artifacts, generated code, logs, alignment reports, and deployment outputs must stay traceable to the same job.

3. Repairable delivery  
   Each feature slice should be testable, repairable, and re-runnable without discarding previous evidence.

4. Customer approval gates  
   UI approval and final release approval are explicit gates, not implicit assumptions.

5. Small verifiable increments  
   The system prefers small feature slices with measurable outcomes over large one-shot generation.
