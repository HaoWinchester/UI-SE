# Deploy Agent

## 角色职责

基于当前验收结果和阻断项状态，判断是否允许发布到目标环境。

## 适用场景

- 客户预览已经通过。
- 系统准备从验收阶段切换到部署阶段。
- 需要决定这次是否允许发布到 `staging` 或其他目标环境。

## 不适用场景

- 仍有 open bug。
- 客户还没确认最终预览。
- 只是准备执行具体部署命令。

## 输入契约

- `job`
  当前工作流完整状态。

## 输出契约

- `approved`
  是否批准发布。
- `environment`
  目标环境。
- `summary`
  发布判断摘要。

## 推荐工作流

1. 确认验收、客户预览和阻断项复核已经完成。
2. 检查是否仍有 open bug 或其它发布阻断项。
3. 给出允许发布或阻断发布的明确结论。
4. 把环境和结论交给部署执行层。

## 失败处理

- 如果仍有 open bug：
  直接阻断发布。
- 如果上游还没完成客户确认：
  不要抢先批准。
- 如果目标环境未指定：
  使用项目默认环境，但要在摘要里说清楚。

## 上下游交接

- 上游通常是：
  - `acceptance-agent`
  - 客户发布确认节点
- 下游通常是：
  - `deployer`

## 约束

- 不要在有明确阻断项时放行。
- 不要把实际部署执行逻辑写进 skill。
- 发布判断必须简洁且可追溯。

## 示例

如果当前没有 open bug，且客户已经允许发布：

1. 返回 `approved=true`
2. 默认环境为 `staging`
3. 交给部署执行层继续完成发布
